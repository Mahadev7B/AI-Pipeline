Closeups — the five smaller calls

Not new screens: the specific decisions Development would otherwise have to improvise. Every number below is measured from the live database this session, not assumed.

1. Where the entry point lives, and what it’s called

The real nav bar with the new item in place. “Ideas”, second, between Overview and Active Work.
Overview Ideas Active Work Pipeline Agents Decisions Progress Risks Meetings Inbox Reviews Releases Automation Costs
“Ideas”, position 2 — recommended
Reads left-to-right as the company’s own lifecycle: Overview (how are we) → Ideas (queued, not started) → Active Work (running) → Pipeline. It is also a noun, like all thirteen existing items — an imperative “New Idea” would be the only verb in the bar, and the page holds saved ideas as well as the form.
“New Idea”, first position
Rejected. Displacing Overview from first position demotes the page the Founder is meant to land on, to promote a form used occasionally. And the label describes the form, not the page.
“Intake” / “Backlog”, last position
Rejected. “Intake” is process vocabulary for a one-person company. “Backlog” names the status, not the activity, and buries the one route in the product that creates work behind twelve read-only registers.

2. Validation and error states

Server-side is authoritative — the browser’s required / maxlength are convenience only. In every one of these states the text the Founder typed is still in the fields. Losing 300 words of typed idea to a validation error is the worst thing this form can do, and it is entirely avoidable.

4. The priority control, and the mess already in the column

The live column holds NULL×15, high×3, medium×1 and four one-off strings like “P0 - Phase 1 Foundation”. Intake writes only the three clean values; the existing rows are disclosed, not cleaned up.

All three options and the current choice are visible without interacting. One click, no typing, no menu — and the default being visibly pre-selected is what makes the field genuinely optional.

Rejected, mildly. Correct and cheap, but hides two of three options behind a click for a field the Founder should be able to ignore at a glance. No other control in this product is a dropdown.
Legacy values, where priority renders
High Medium Low P0 - Phase 1 Foundation —
Only high gets the accent; medium and low are gray. Priority is a hint, not a status, and every colour in this palette already means a status. An unrecognised legacy value renders verbatim in the dimmest gray — never mapped to a known colour, never hidden, never crashed on. NULL renders as an honest em dash.

5. The “stuck after 3 days” badge on a parked idea

Product flagged this and derived_state.py’s own docstring records it as unresolved: task_is_stuck() excludes only BLOCKED, FOUNDER_APPROVAL and DONE, so a BACKLOG idea starts being flagged as stuck on day four. This milestone makes that non-latent on day one.
What ships if nobody decides
TASK-025 — Divergent-thinking stage…
No activity in 4d · threshold 3d
Wrong
An idea the Founder deliberately parked four days ago is reported as a failure of the company to act on it. The badge is telling the truth about elapsed time and lying about what it means.
Recommended
TASK-025 — Divergent-thinking stage…
Not started
In Backlog 4d · waiting for you to start it
Design position
Exclude BACKLOG from task_is_stuck(), the same way BLOCKED and FOUNDER_APPROVAL are excluded and for the same reason: the status already has a better-labelled treatment of its own. The age stays visible — “In Backlog 4d” is honest and useful — it is just not framed as a failure. CTO owns the code decision; this is the behaviour the screen needs.
